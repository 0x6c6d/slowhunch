# T020: Push after commit

Phase 5 · Model: opus: sends history to a live remote; must never lose or force (A17, Risk: push) · Depends-on: T019 · Covers: R35, R21, R12 (git pushed)

## Brief
After the run's commit, push when asked (`internal/cli` run helper from the pull task, `internal/report`).

- Push happens after a successful commit of a vault-changing command when (`git.push` is true or `--push`
  is given) and `--no-push` is not given, the vault has the remote `git.remote`, and not `--dry-run`.
  Branch = `git.branch` or the current branch. Call `gitops.Repo.Push(remote, branch)`; plain push only.
- A run that made no commit still pushes when asked and the local branch is ahead of its upstream
  (pending earlier commits), so a failed push is retried by the next pushing run; with no upstream and no
  new commit it does nothing.
- Failure: `PUSH_FAILED` warning (in `errors` for `add`/`collide` reports, else in `warnings`), the commit is
  kept, exit 0. Never retry inside the run, never force.
- New global flags `--push` and `--no-push` (`Env.Push`, `Env.NoPush`); `--push --no-push` together fails
  `BAD_INPUT`.
- The `git` object gains `pushed` (bool). `report.GitInfo` gets `Pushed bool json:"pushed"`.

Tests in `internal/cli/`: `TestPushOptIn` (`git.push` true: the bare remote receives the commit,
`pushed: true`); `TestPushDefaultOff` (default config pushes nothing, `pushed: false`); `TestPushFlags`
(`--push` with `git.push` false pushes; `--no-push` with `git.push` true does not; both flags fail
`BAD_INPUT`); `TestPushFailedRetried` (remote URL broken: `PUSH_FAILED` warning, commit kept, exit 0; after
fixing the URL the next pushing run sends both commits); `TestPushThenPull` (A pushes with `git.push` true,
B pulls it before its next write: the two-clone flow of R34 + R35 end to end).

## Verification
`.harness/verify/v2/T020.sh` exits 0. It runs the five tests and the cli package; with the built binary and
a local bare remote it checks that `git.push` true updates the bare repo, and (negative) that the default
config and `--no-push` leave the bare repo unchanged and `--push --no-push` fails `BAD_INPUT`.
