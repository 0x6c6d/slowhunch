# T001: Config v2 keys, defaults and validation

Phase 1 · Model: sonnet: multi-field config structs with defaults and load-time validation · Depends-on: T000 · Covers: R25, R27, R28, R31, R32, R33, R34, R35, R18, R23

## Brief
Extend `internal/vault/config.go` (and `internal/vault/store.go` for state) with the v2 configuration. Tests go
in `internal/vault/config_test.go` as `TestConfigV2` (one top-level test, subtests allowed).

New keys (JSON names exact), all with defaults in `DefaultConfig()` and all optional in `config.json`
(values omitted keep their defaults, as in v1):
- `collide`: `max_cosine` float 0.15, `aesthetic_weight` float 2.0, `max_pairs` int 6.
- `review`: `stale_days` int 60.
- `place.wildcard_share` float 0.10 (add to the existing `PlaceConfig`).
- `pdf.command` []string, default `["pdftotext", "-layout", "{file}", "-"]`.
- `media`: `map[string]map[string]ProviderConfig` = medium -> role -> provider override (default empty).
- `caps.by_medium`: `map[string]MediumCaps` with `runs_per_day` int and `tokens_per_run` int
  (absent or 0 = unlimited) on the existing `CapsConfig`.
- `git`: keep `commit` (default true) and add `pull` bool default true, `require_pull` bool default false,
  `push` bool default false, `remote` string default `origin`, `branch` string default empty (= current branch).
  Booleans whose default is true must stay true when the key is omitted (decode over the defaults, as v1 does).

Go names (other tasks use them): `Config.Collide CollideConfig{MaxCosine, AestheticWeight, MaxPairs}`,
`Config.Review ReviewConfig{StaleDays}`, `Config.PDF PDFConfig{Command}`, `Config.Media
map[string]map[string]ProviderConfig`, `CapsConfig.ByMedium map[string]MediumCaps{RunsPerDay, TokensPerRun}`,
`PlaceConfig.WildcardShare`, `GitConfig{Commit, Pull, RequirePull, Push, Remote, Branch}`.

Validation in `LoadConfig` (fail with `errs.Fatal(errs.BadInput, ...)` and a hint naming the bad key):
- a key of `roles` that is not one of `gate extract place collide`;
- a key of `media` that is not a known medium (`vault.Mediums`), or a role key under it outside those four roles;
- a key of `caps.by_medium` that is not a known medium; negative `runs_per_day`/`tokens_per_run`;
- `collide.max_cosine` outside [0,1], `collide.aesthetic_weight` <= 0, `collide.max_pairs` < 1,
  `review.stale_days` < 1, `place.wildcard_share` outside [0,1], an empty `pdf.command` given explicitly
  (`[]`), an empty `git.remote` given explicitly.

State: add `RunsByDay map[string]map[string]int` with JSON name `runs_by_day` (date `YYYY-MM-DD` -> medium ->
count) to `vault.State`; it is `omitempty` so v1 state files and v1 tests stay byte-compatible.

`MarshalConfig(DefaultConfig())` (written by `init`) must include the new sections so owners can see them;
adapt any v1 test that compares the init config bytes or file list, and keep `slowhunch init` working.

`TestConfigV2` must cover: every default above; a partial file overriding one field per section while the
others keep defaults (including `git.pull` staying true when only `git.push` is set); each invalid case
listed above failing `BAD_INPUT`; a `state.json` round trip with `runs_by_day`.

## Verification
`.harness/verify/v2/T001.sh` exits 0. It runs `TestConfigV2` and the whole vault package, and checks with the
built binary that `init` writes a config containing `max_cosine`, `wildcard_share`, `pdftotext` and
`require_pull`, and that a config with an unknown role key makes a command fail with `BAD_INPUT`.
