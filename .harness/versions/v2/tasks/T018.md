# T018: gitops pull, push, behind

Phase 5 · Model: opus: new git subprocess calls against a live remote (A14-A17, Risk: pull/rebase, push) · Depends-on: T003 · Covers: R34, R35, R37, R38, R39, R22 (git remote)

## Brief
Extend `internal/gitops/gitops.go` (argv only, through the existing `run` helper or a variant of it; no
shell). New methods on `*Repo`:

```go
func (r *Repo) HasRemote(name string) (bool, error)        // git remote (list) contains name
func (r *Repo) CurrentBranch() (string, error)             // symbolic-ref --short HEAD
func (r *Repo) HasUpstream() (bool, error)                 // rev-parse --abbrev-ref --symbolic-full-name @{u}
func (r *Repo) Head() (string, error)                      // rev-parse HEAD
func (r *Repo) PullRebase() (pulled int, err error)        // pull --rebase --autostash
func (r *Repo) Push(remote, branch string) error           // push <remote> <branch>
func (r *Repo) Behind() (int, error)                       // rev-list --count HEAD..@{u}; 0 without upstream
```
Rules:
- `PullRebase` records HEAD and `status --porcelain` first, runs `pull --rebase --autostash` with the same
  identity options as `Commit`, and returns `pulled` = number of commits between the old HEAD and the new
  HEAD that were not in the old HEAD (`rev-list --count old..new`). It never creates a merge commit.
- On failure: if `diff --name-only --diff-filter=U` lists files, run `rebase --abort`, then check HEAD and
  `status --porcelain` equal the recorded values, and return `errs.New(errs.Conflict, "pull conflicts in
  <files>", "resolve the conflict with git yourself, then run again")` with `Extra{"paths": files}` (exit 4).
  If the restore check fails, say so in the message (never hide it). Any other failure (unreachable remote,
  no such repo) returns `errs.New(errs.PullFailed, <first stderr line>, "check git.remote and your network")`.
  slowhunch never resolves a conflict and never picks a side.
- `Push` runs exactly `push <remote> <branch>`; failure returns `errs.New(errs.PushFailed, <first stderr
  line>, "the commit is kept; the next run that pushes sends it")`. Remote and branch must be non-empty
  and must not start with `-` or `+` (`BAD_INPUT`).
- Network-touching calls (`pull`, `push`) run with `GIT_TERMINAL_PROMPT=0` added to the environment and
  a timeout (120 s) so they never hang waiting for credentials.
- Never add `fetch`, `reset`, `--force`, `-f`, `--force-with-lease`, `+` refspecs, `filter-branch` or any
  history rewrite; the policy tests `TestNoForceGit`/`TestGitOnlyGitops` must still pass.

Tests in `internal/gitops/gitops_test.go` (bare repo under `t.TempDir()` as `origin`, two clones, isolated
git config env): `TestPullRebase` (B pulls A's 2 commits: pulled 2, linear history, no merge commit; local
uncommitted change survives via autostash; no upstream case handled by callers: `HasUpstream` false);
`TestPushPlain` (push sends the commit; bad remote name `-x` rejected); `TestPushFailed` (`PUSH_FAILED`,
commit kept); `TestBehindCount` (after `git fetch` in the test, Behind = 1; no upstream = 0);
`TestRebaseConflictAborts` (diverging edits to one file: `CONFLICT` naming the file, no rebase in progress,
HEAD and working tree exactly as before); `TestPullFailedUnreachable` (remote URL to a missing path:
`PULL_FAILED`).
