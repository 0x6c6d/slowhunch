# T005: review command

Phase 1 · Model: sonnet: thin cli command over an existing read-only query · Depends-on: T004 · Covers: R27

## Brief
Add `internal/cli/cmd_review.go` registering `review` with summary
`list stale hunches, orphans and unplaced aesthetic atoms (read-only) [--stale-days N]`.

- Flag `--stale-days N` (also `-stale-days`), default from config `review.stale_days`; N < 1 fails `BAD_INPUT`.
- Opens the vault (`env.openVault()`), loads the index, calls
  `synth.RunReview(v, ix, env.Now(), days)` and returns it. `--json` output is the standard envelope with the
  keys `stale_hunches`, `orphans`, `unplaced` (each an array of ids, `[]` when empty). Text output lists the
  three groups with their ids, one per line, using `[[id]]` form. Exit 0, also when lists are non-empty.
- Read-only: no transaction, no commit, no state or audit write, no provider.

Tests in `internal/cli/cmd_review_test.go`, top-level `TestReviewCommand`: seed a temp vault through
`Run([]string{"init", ...})` and `create`/`hunch add` commands (and hand-written files where a date must be in
the past), run `review --json`, assert the exact lists, assert `--stale-days 0` fails `BAD_INPUT`, and assert
the vault tree (every file's bytes, plus `git rev-parse HEAD` when git is available) is unchanged.

## Verification
`.harness/verify/v2/T005.sh` exits 0. It runs `TestReviewCommand`, and with the built binary on a fresh vault
checks that `review --json` returns three empty arrays with exit 0, changes no file, and (negative) that
`review --stale-days 0` fails with `BAD_INPUT`.
