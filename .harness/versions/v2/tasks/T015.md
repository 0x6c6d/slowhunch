# T015: Collide pair selection

Phase 4 · Model: sonnet: deterministic selection algorithm over the TF-IDF index, pure function · Depends-on: T001 · Covers: R25

## Brief
Add `internal/synth/collide.go` with the pure, model-free pair selection (no writes, no provider):

```go
type Item struct{ ID, Type, Medium, Stance, Text string; Aesthetic bool }
type Pair struct{ A, B string; Cosine, Score float64; Reserved bool } // A < B
type Selection struct{ Pairs []Pair; Candidates int; Capped bool }
func Pool(ix *vault.Index) []Item
func Select(items []Item, existing map[[2]string]bool, cfg vault.CollideConfig, limit int) Selection
```
- `Pool`: live notes (atoms, not archived) plus hunches with `state` `open` or `warming`. `Text` = title or
  claim/question + body. `Medium` from `ix.MediumOf`, `Stance` from the note (empty for hunches),
  `Aesthetic` = `vault.IsAesthetic(Medium)`. Sorted by id.
- Build a TF-IDF index (`internal/search`) over the pool's texts; for every unordered pair (A < B by id)
  compute the cosine. Candidates = pairs with `cosine <= cfg.MaxCosine` that are not in `existing` (pairs
  already listed in some proposal's `items`, either order).
- Score = `(1 - cosine)`, multiplied once by `cfg.AestheticWeight` when either item is aesthetic.
- Max pairs `n = cfg.MaxPairs`, lowered (never raised) by `limit` when `limit > 0`.
- Reserved quota `r = floor(0.25 * n)`, and at least 1 when `n >= 4`: filled first from candidates that are
  an `asserts` note x a `reads` note with different media, highest score first; then the rest by score.
  Order everywhere: score descending, then `(A, B)` ascending. If fewer reserved candidates exist, the
  rest of the slots go to the general order.
- `Capped` = true when candidates > selected pairs; `Candidates` = number of candidates.
- Fully deterministic: the same input gives the same output (no map iteration order leaks).

Also add `existing` collection helper `ExistingPairs(ix *vault.Index) map[[2]string]bool` reading every
proposal's `items` (pairs of the first two ids; a proposal with fewer than two items is ignored).

Test `TestCollideSelect` in `internal/synth/collide_test.go` (hand-built items, and a small seeded vault for
`Pool`/`ExistingPairs`): only pairs with cosine <= 0.15; an aesthetic pair outranks an equal-cosine factual
pair; `max_pairs` 6 with 10 candidates gives 6 and `Capped`; reserved `asserts` x `reads` cross-medium pair
included even when its score is lower; `limit` 2 lowers, `limit` 99 does not raise; existing pairs skipped
in both orders; same-medium asserts x reads is not reserved; two calls give identical results.
