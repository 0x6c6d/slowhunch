# T016: collide command and proposals

Phase 4 · Model: opus: model output becomes file names and vault writes (Risk: path confinement / prompt injection) · Depends-on: T007 T015 · Covers: R26, R25, R12 (collisions)

## Brief
Add `internal/cli/cmd_collide.go` (`collide [--limit N] [--dry-run]`, summary
`pair distant notes and hunches and write proposals [--limit N]`) and the proposal building in
`internal/synth/propose.go`.

- `--limit N`: N >= 1, else `BAD_INPUT`. Load the index, `synth.Pool`, `synth.ExistingPairs`,
  `synth.Select(items, existing, cfg.Collide, limit)`.
- `--dry-run`: print the selected pairs, `counts` and `capped`; no model call, no write, no commit.
- Per pair one model call with role `collide` via `provider.ForRole(cfg, "collide", medium)` (medium of the
  first item) and `provider.CallJSON`, system prompt = the vault's `collide` prompt, user text = the two
  items (id, type, medium, stance, claim/question, excerpt cut to `place.excerpt_chars`) fenced with
  `intake.NewDelimiter`/`intake.Fence` like the other roles (`excerpt_only`). Never send a whole file.
- Validate the reply in code: `idea` 1-200 chars and `cheapest_test` 1-400 chars after trimming, `keep`
  boolean, no secret-like text (`intake.ContainsSecret`); ids are taken from the pair, never from the reply.
  An invalid reply or provider error -> an `errors` entry `{item: "<a>+<b>", code, reason}`, other pairs go on.
- `keep: true` -> write `proposals/<slug>.md`: type `proposal`, `items: [a, b]`, `idea`, `cheapest_test`,
  `status: open`, `bears_on` = the hunch ids among a and b, created/updated/author/rev as other writes.
  `<slug>` = kebab-case of the idea, only `[a-z0-9-]`, at most 60 chars, never empty (fallback
  `collide-<a>-<b>` sanitized), collision suffix as in v1 id generation; written only through the vault
  transaction (`PutDoc`), so path confinement applies. `keep: false` writes nothing and is not remembered.
- Collide never writes notes or hunches and never changes a proposal status.
- One transaction (command `collide`), one commit for the run when anything was written; a run that keeps
  nothing makes no commit. Report saved like `add` reports with `collisions: [{items: ["[[a]]","[[b]]"],
  proposal: "[[slug]]"}]` (`report.Collision` type replacing `[]any`), `counts` with `pairs_candidates`,
  `pairs_tried`, `pairs_kept`, and `capped` reported in the output (bool) and in `errors` as a warning
  `{item: "collide", code: "CAP_REACHED", reason: "max_pairs <n> of <m> candidates"}` when the cap bites.
  `cost` records role `collide`.
- Re-running on an unchanged vault: kept pairs are skipped (existing), so nothing is written.

Tests in `internal/cli/cmd_collide_test.go` (exec provider with the fake model helper answering `collide`):
`TestCollideRun` (seeded vault with asserts/reads notes in different media, an aesthetic note and an open
hunch): proposals written with valid frontmatter, `items` and `bears_on`, report `collisions` and counts,
cap reported, one commit, notes and hunches byte-identical. `TestCollideRerun`: second run writes nothing
and makes no commit. `TestCollideDryRun`: no model call, no file change. `TestCollideHostileReply`: an idea
of `../../etc/passwd x` produces a slug inside `proposals/` only; an over-long idea, an empty
`cheapest_test` and a reply with `sk-` secret are rejected as pair errors with nothing written for them.
