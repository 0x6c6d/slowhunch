# T019: Pull before write in the run wrapper

Phase 5 · Model: opus: cross-cutting run order before every write (A14-A16, Risk: pull/rebase, data loss) · Depends-on: T001 T002 T018 · Covers: R34, R38, R21, R12 (git pulled)

## Brief
Make every vault-changing command pull before it reads the index (`internal/cli`, `internal/vault/txn.go`
only if needed, `internal/pipeline` only to accept the pulled count, `internal/report/report.go`).

Vault-changing commands: `add` (single and `--from`), `create`, `update`, `delete`, `link`, `unlink`,
`hunch add`, `hunch evidence`, `hunch state`, `collide`, `keep`. `init` never pulls.

Order for each run (one shared helper, e.g. `env.prepareRun(v, cfg)`, called by every command above before
it loads the index or calls a provider):
1. resume: commit pending files recorded in `state.json` (v1 crash resume, unchanged);
2. dirty check as in v1 (foreign uncommitted vault files -> `CONFLICT`);
3. pull: only when git is available, commits are enabled, the vault has the remote `git.remote` and the
   current branch has an upstream, `git.pull` is true, and neither `--no-pull` nor `--dry-run` is given:
   `gitops.Repo.PullRebase()`;
4. the command then loads the index (so placement and collide see pulled notes), runs, and commits as in v1.

Outcomes:
- `CONFLICT` from the pull: the command stops before any write, exit 4, nothing written, error lists paths.
- `PULL_FAILED`: when `git.require_pull` is false, the run continues locally and the failure appears as a
  warning: in `errors` for report-producing commands (`add`, `collide`), otherwise in a top-level `warnings`
  array of `{code, message, hint}`; exit 0. When `git.require_pull` is true the command stops with
  `PULL_FAILED`, exit 1, before any provider call or write.
- No remote or no upstream: pull is a silent no-op (`pulled: 0`).
- New global flag `--no-pull` (parsed in `Run` like `--dry-run`) and `Env.NoPull`.
- The `git` object of every vault-changing result and of the `add`/`collide` reports gains `pulled` (int,
  commits pulled). `report.GitInfo` gets `Pulled int json:"pulled"`.

Tests in `internal/cli/` (new file `sync_test.go` or similar; bare remote + two vault clones, fake model via
the exec helper, isolated git env): `TestPullBeforeWrite` (A creates a note-bearing entry and the test pushes
it with git; B's next `add` pulls it first, reports `pulled: 1`, and placement sees it: B's index or the
place request includes A's id); `TestPullNoPullFlag` (`--no-pull` leaves B behind); `TestPullNoRemote`
(vault without remote works as v1, `pulled: 0`); `TestPullFailed` (remote path removed: warning
`PULL_FAILED`, write happens, exit 0); `TestPullFailedRequire` (`git.require_pull` true: exit 1, nothing
written, HEAD unchanged); `TestRebaseConflictCLI` (A and B both create the topic with the same id, B commits
with `--no-pull`, B's next write fails `CONFLICT` exit 4 naming the file, B's tree and HEAD unchanged, no
rebase in progress). All v1 tests keep passing.

## Verification
`.harness/verify/v2/T019.sh` exits 0. It runs the six tests and the cli and pipeline packages; with the
built binary and a local bare remote it checks that B's `create` pulls A's pushed commit (`pulled` 1) and
(negative) that `git.require_pull` with an unreachable remote fails `PULL_FAILED` with HEAD unchanged, and
that a same-id topic created in both clones fails `CONFLICT` (exit 4) with B's tree unchanged.
