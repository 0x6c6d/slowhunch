# T004: Review queries in internal/synth

Phase 1 · Model: sonnet: read-only queries over the existing index, moderate judgment · Depends-on: T001 · Covers: R27

## Brief
Create the new package `internal/synth` (`internal/synth/review.go`, package doc comment
"Package synth holds the synthesis steps: collide pair selection and review queries.") with a read-only,
model-free review over a loaded vault:

```go
type Review struct {
    StaleHunches []string `json:"stale_hunches"` // ids, sorted
    Orphans      []string `json:"orphans"`       // ids, sorted
    Unplaced     []string `json:"unplaced"`      // ids, sorted
}
func RunReview(v *vault.Vault, ix *vault.Index, today time.Time, staleDays int) (Review, error)
```
All three slices are non-nil (empty JSON arrays, never `null`).

Rules:
- **Stale hunch**: a hunch with `state` `open` or `warming` whose last activity is more than `staleDays`
  days before `today` (local date). Last activity = the newest of: the hunch's `created` date, the `date` of
  every `evidence` entry, and the `time` of every `.slowhunch/audit.log` line whose `paths` contain the
  hunch's file path (the audit log stores paths only, so a recorded change of the hunch file, such as a
  `revisit` change, counts). A missing or unreadable audit log counts as empty; a malformed line is skipped.
  `tested`/`dropped` hunches are never stale.
- **Orphan**: a live note (type `note`, not archived) with no backlinks (`ix.Backlinks`) and no outgoing
  links (`ix.Outgoing`).
- **Unplaced aesthetic atom**: a live note whose medium (`ix.MediumOf`) is aesthetic (`vault.IsAesthetic`)
  with an empty `rereads` list, no backlinks, and that is not named (as `atom` or `echoes`, `[[id]]` form)
  in the `echoes` of any saved report under `.slowhunch/reports/` (read them with `report.LoadAll`; if that
  creates an import cycle, read the JSON files directly with the vault read API).
- Reads only: `RunReview` never writes a file, never touches git, never calls a provider.

Tests in `internal/synth/review_test.go`, top-level `TestReviewQueries`: build a seeded temp vault (write
files through the vault write API or `vault.Txn` with `NoCommit`) containing one stale open hunch, one
fresh open hunch with a recent evidence entry, one `tested` old hunch, one hunch made fresh only by an
audit-log line, one orphan note, one linked note, one aesthetic note with `rereads`, one aesthetic note
named in a saved report's `echoes`, and one unplaced aesthetic note. Assert the three exact lists, and
assert a hash of every file under the vault is identical before and after the call.
