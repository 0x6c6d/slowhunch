# T017: keep command

Phase 4 · Model: sonnet: a cli command over the existing topic-append write path · Depends-on: T000 · Covers: R29

## Brief
Add `internal/cli/cmd_keep.go`: `slowhunch keep "<text>" --ids a,b [--topic ID]`, summary
`append a dated note linking ids to a topic`.

- Checks, all before any write, in this order: exactly one positional text, non-empty after trimming
  (`BAD_INPUT`); text longer than 2,000 characters (runes) -> `TOO_LONG`; secret-like text
  (`intake.ContainsSecret`) -> `BAD_INPUT`; `--ids` required, comma-separated, each id must exist in the index
  (`NOT_FOUND` naming the id); `--topic ID` must be an existing entry of type `topic` (`NOT_FOUND`); without
  `--topic` the nearest topic is chosen by TF-IDF cosine between the text and each topic's title + body
  (ties: lowest id); no topics in the vault -> `NOT_FOUND` with hint "create a topic first".
- Append block to the topic body: a blank line, `### YYYY-MM-DD` (local date from `env.Now()`), the text,
  then one line with `[[a]] [[b]]` (ids in the given order, space separated). Write it through the same
  transaction path and rev check as `update --append` (reuse its code; do not duplicate the write logic):
  one transaction with command `keep`, one commit, new `rev` returned.
- Result `{id: <topic>, rev, path, git: {commit}}`. No other file is created or changed.

Tests in `internal/cli/cmd_keep_test.go`: `TestKeepNamed` (append to `--topic`, body ends with the dated
block, rev changed and equal to the computed rev, one commit); `TestKeepNearest` (two topics, the text
matches the second); `TestKeepFailures` (missing id, unknown topic, no topics, secret text `sk-` + 20
letters, 2,001 characters: each fails with the right code and the vault tree and HEAD are unchanged;
exactly 2,000 characters succeeds).

## Verification
`.harness/verify/v2/T017.sh` exits 0. It runs the three tests; with the built binary on a fresh vault with
one topic, `keep` with a real id appends the block and makes a commit, and (negative) an unknown id fails
`NOT_FOUND`, 2,001 characters fail `TOO_LONG`, and a vault with no topic fails `NOT_FOUND`, each with HEAD
unchanged.
