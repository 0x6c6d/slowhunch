# T015: update command: field patch with rev, topic append

Phase 3 · Model: opus: stale-write protection is Consequential assumption 5 and evidence immutability is a data-loss Risk item · Depends-on: T014 · Covers: R5, R14 (update), R17 (exit 4)

## Brief
Add `internal/cli/cmd_update.go` + tests. Use `env.openVault/begin/today`, `docFromJSON`/`docToJSON` (in `internal/cli/docjson.go`), `(*Vault).LoadIndex`, `vault.Validate`, `vault.NoteBody`, `(*Txn).PutDoc/Commit`, `frontmatter.Rev`.

`update <id> --rev <rev> (--data <json|-> | --append <text|->)`:
- `--rev` is mandatory: missing → BAD_INPUT exit 2 ("update needs --rev; get the current rev with slowhunch get"). Exactly one of `--data` / `--append` (else BAD_INPUT). Unknown id → NOT_FOUND.
- Stale rev: `PutDoc` returns CONFLICT_REV (exit 4); the JSON error carries `current` (the file's full current content) and `rev` (current rev). Nothing is written.
- `--data`: a JSON object patch. Each key sets that field (same value conversion as create); a `null` value deletes the field. Keys `id type created rev` → BAD_INPUT. For notes, any change to `evidence` → BAD_INPUT ("evidence is never rewritten; create a new atom instead"); if `claim` changes, the body is regenerated with `NoteBody(claim, evidence)`. Sets `updated` = today. `vault.Validate` must pass before writing.
- `--append`: only for `topic` (else BAD_INPUT "append works on topics only"); appends `"\n" + text` to the body (text trimmed, at least one character); sets `updated`.
- A patch that changes nothing (same bytes) succeeds without writing or committing.
- One commit (`ids [id]`, counts `updated: 1`). Result: `{"id", "rev", "path", "git": {"commit"}}`.

Tests (`internal/cli/cmd_update_test.go`): `TestCRUDUpdatePatch` (tags patch with current rev → new rev, `updated` set, one new commit), `TestCRUDUpdateStaleRev` (old rev → exit 4, code CONFLICT_REV, JSON contains `current` equal to the file content, file unchanged), `TestCRUDUpdateNoRev` (exit 2), `TestCRUDUpdateEvidence` (exit 2, file unchanged), `TestCRUDUpdateAppend` (topic append works; append on a hunch → exit 2), `TestCRUDUpdateDelete` (null removes a field).

## Verification
`.harness/verify/v1/T015.sh` exits 0. It runs the named tests and a binary patch; negatives: a stale rev must exit 4 with CONFLICT_REV and current content, a missing rev must exit 2, an evidence rewrite must be refused, each leaving the file byte-identical.
