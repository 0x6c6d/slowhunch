# T020: source facts command

Phase 3 · Model: haiku: one read-only command over existing helpers · Depends-on: T007, T011, T013 · Covers: R14 (source facts), R8 (stored text is the ground truth)

## Brief
Add `internal/cli/cmd_source.go` registering the two-word command `source facts`, + test. Use `env.openVault()`, `(*Vault).LoadIndex`, `(*Vault).ReadFile`, `vault.InboxLines(stored, medium)`.

`source facts <id>`:
- `<id>` must be an indexed entry of type `source` (else NOT_FOUND; an existing non-source → BAD_INPUT).
- Read `inbox/<id>.txt` (NOT_FOUND with hint "this source has no stored text" if missing). `medium` comes from the source's `medium` field.
- Lines = `vault.InboxLines(stored, medium)` (numbered media are stored as `N<TAB>line`; plain media are numbered here on the fly, starting at 1).
- JSON result: `{"id", "medium", "lines": [{"n": 1, "text": "..."}], "count": N}`. Text mode: each line as `printf("%4d  %s\n", n, text)`.
- Read-only: no txn, no audit.

Test `TestSourceFacts` (`internal/cli/cmd_source_test.go`): in a temp vault (init via `Run`), write `sources/poem-larkin-trees-ab12.md` (a valid source doc: `id type created updated added_by rev medium title author`) and `inbox/poem-larkin-trees-ab12.txt` = `vault.FormatInbox("The trees are coming into leaf\nLike something almost being said;", "poem")` through the vault API; `source facts` returns 2 lines with n 1 and 2 and the plain text; a plain `article` source is numbered on the fly; a missing id → exit 2 NOT_FOUND.

## Verification
`.harness/verify/v1/T020.sh` exits 0. It runs `TestSourceFacts` and checks the command is registered; negative: an unknown source id must fail with NOT_FOUND.
