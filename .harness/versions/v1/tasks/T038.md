# T038: add crash resume, dirty-file conflict, exact commit

Phase 6 · Model: opus: crash resume is Consequential assumption 12 and dirty-file conflicts protect against data loss · Depends-on: T036 · Covers: R13 (crash resume), R21

## Brief
Prove (and fix where needed) that `pipeline.Add` honours the git rules end to end. Production code changes, if any, stay in `internal/pipeline/` (and, only if a real bug is found there, `internal/vault/txn.go`). Tests in `internal/pipeline/git_test.go`, using temp vaults with `gitops.Init`, `gitops.New(root)` as `Deps.Committer`, and fake providers.

Behaviour to guarantee:
- Conflict: if any file the run would write or modify (inbox file, source, notes, a `--hunch` hunch, a duplicate/contradiction target) has uncommitted changes the run did not make, `Add` returns `errs.Conflict` (exit 4) before writing anything: vault tree and git HEAD unchanged, no state pending entries, no report file.
- Exact commit: a normal run commits exactly the files it wrote or modified (`git show --name-only HEAD`); an unrelated modified tracked file and an unrelated staged file stay uncommitted and unchanged.
- Crash resume: if the process dies after writing some files but before committing, the paths stay in `.slowhunch/state.json` `pending`; the next vault-changing run (another `Add`, or any txn) commits them together with its own files in one commit, and they do not count as a CONFLICT. Simulate the crash with a `Committer` wrapper whose `Commit` returns an error the first time (and check that `Add` then returns an error and leaves files on disk with `pending` recorded).
- `NoCommit`: files written, no commit, `Report.Git.Skipped == "no-commit"`.

Tests: `TestConflict` (dirty `--hunch` file → CONFLICT, nothing written), `TestConflictUntrackedTarget` (an untracked foreign file at the exact inbox path → CONFLICT), `TestCommitExact`, `TestResume` (crash then next add: one commit containing both runs' files; `pending` empty afterwards), `TestNoCommitFlag`.
