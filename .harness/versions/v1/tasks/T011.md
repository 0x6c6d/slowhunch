# T011: In-memory index, backlinks, neighbourhood

Phase 2 · Model: sonnet: read-only aggregation over the parser and schema · Depends-on: T007, T008 · Covers: R6 (computed backlinks), R14 (graph basis)

## Brief
Add `internal/vault/index.go` (package `vault`) + tests. The index is rebuilt in memory from the files on every command (no on-disk cache). It must load 2,000 notes plus their sources well under one second.

API (exact):
```go
type Entry struct { ID, Type, Path string; Doc *frontmatter.Doc; Raw []byte }   // Path is vault-relative
type LoadError struct { Path string; Err error }
type Index struct { /* unexported */ }
func (v *Vault) LoadIndex() (*Index, []LoadError, error)
func (ix *Index) Get(id string) (*Entry, bool)
func (ix *Index) All() []*Entry                    // sorted by id
func (ix *Index) OfType(typ string) []*Entry       // sorted by id
func (ix *Index) Outgoing(id string) []string      // Links(doc) of that entry
func (ix *Index) Backlinks(id string) []string     // ids whose Outgoing contains id; sorted
func (ix *Index) Neighbourhood(id string, depth int) (nodes []string, edges [][2]string) // BFS over outgoing and incoming links up to depth; nodes sorted, start included; edges as {from,to}, sorted, deduplicated
func (ix *Index) MediumOf(id string) string        // source: its medium; note: medium of its `source` entry; else ""
```
Rules:
- Read `*.md` directly under `notes/ sources/ hunches/ proposals/ topics/` (not `archive/`, not `inbox/`, not subfolders). The id is the file name without `.md`; `Type` is the doc's `type` field.
- A file that fails `frontmatter.Parse`, whose `type` does not match its folder (`Folder(type)`), or whose `id` field differs from the file name, becomes a `LoadError` and is not indexed. A duplicate id across folders is a `LoadError` for the second file (folders scanned in the order above, files sorted).
- `LoadIndex` does not call `Validate` (lint and verify do their own checks). It only returns a non-nil error for I/O failures on the folders themselves.
- Links to unknown ids are kept in `Outgoing` (verify reports them); `Backlinks` only lists existing entries.

Tests (`internal/vault/index_test.go`, temp vaults written with `frontmatter` + `Vault.WriteFile`): `TestIndexLoad` (all five folders, archive ignored, broken file reported as LoadError, wrong-folder type reported), `TestBacklinks` (links via `[[id]]` in a body, `bears_on`, `links`, `source`, hunch evidence note), `TestNeighbourhood` (depth 1 vs 2 on a small chain), `TestMediumOf`.
