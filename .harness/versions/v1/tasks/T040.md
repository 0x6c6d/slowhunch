# T040: Agent sequence, schema and exit-code coverage tests

Phase 7 · Model: sonnet: cross-command tests over finished commands · Depends-on: T015, T016, T018, T019, T023, T039 · Covers: R14, R17

## Brief
Add `internal/cli/agent_test.go` (tests only; fix production code in `internal/cli/` only if a test exposes a real bug, and say so in your report). Call `Run` in-process with `--json` and `--vault`; decode each stdout as JSON.

- `TestAgentSequence`: on a fresh vault (init): `create source` (medium article, title, author), `create note` with that `source`, stance asserts, claim and evidence; `link` the note to a new topic; `hunch add`; `hunch evidence <hunch> --note <note> --relation supports`; `delete <topic>` (soft; file now in `archive/`); `lint` exits 0; `backlinks <note>` returns valid JSON. Every step exits 0, nothing is ever overwritten (each create returns a fresh id), and each vault-changing step adds exactly one commit (count with `git rev-list --count HEAD`).
- `TestSchemaAllCommands`: for every registered command name (iterate the registry), run it with minimal valid arguments on a seeded vault (or with no arguments for those that require some) and `--json`; every stdout must parse as JSON with `"schema": 1` and, for errors, an `error` object with non-empty `code`, `message` and `hint` keys (hint may be empty string but must be present).
- `TestExitCodesAll`: one case per exit code, each asserting stdout JSON and the code: 0 (`list`), 1 (`config.json` replaced by invalid JSON → any vault command), 2 (unknown command; `update` without `--rev`), 3 (`lint` with a `crafts` note carrying `confidence`), 4 (`update` with a stale `--rev` → CONFLICT_REV).
