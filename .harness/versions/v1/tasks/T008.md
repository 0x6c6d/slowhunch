# T008: Vault write path: confinement, atomic write, CONFLICT_REV, audit, state, test guard

Phase 2 · Model: opus: path confinement, atomic writes, stale-rev protection and the test guard are security and data-loss Risk items (Consequential assumption 5) · Depends-on: T005 · Covers: R5, R24, R8 (inbox immutable)

## Brief
Add the single write path to package `vault` (`internal/vault/store.go`, `guard.go` + tests). Every later write in the product goes through these functions.

API (exact):
```go
type Vault struct { Root string }                 // absolute, symlinks resolved
func Open(root string) (*Vault, error)            // GuardPath(root); <root>/.slowhunch must be a directory, else NOT_FOUND
func GuardPath(path string) error                 // SLOWHUNCH_TEST=1 and path (resolved) equal to or inside any dir in SLOWHUNCH_PROTECTED (os.PathListSeparator-separated) -> BAD_INPUT "refusing protected path"
func (v *Vault) Abs(rel string) (string, error)   // confinement check, see below
func (v *Vault) Exists(rel string) bool
func (v *Vault) ReadFile(rel string) ([]byte, error)          // NOT_FOUND if missing
func (v *Vault) WriteFile(rel string, data []byte) error      // atomic
func (v *Vault) Move(from, to string) error                   // both confined; target must not exist (EXISTS)
func (v *Vault) Remove(rel string) error
func (v *Vault) PutDoc(rel string, d *frontmatter.Doc, expectRev string) (string, error)
type AuditEntry struct { Time, RunID, Command string; Paths []string; PromptVersions map[string]string; Commit string }  // JSON tags: time run_id command paths prompt_versions commit
func (v *Vault) Audit(e AuditEntry) error                     // append one JSON line to .slowhunch/audit.log (O_APPEND)
type State struct { PromptVersions map[string]string `json:"prompt_versions"`; Pending []string `json:"pending"` }
func (v *Vault) LoadState() (State, error)                    // missing file -> zero State
func (v *Vault) SaveState(s State) error                      // .slowhunch/state.json, atomic
```
Rules:
- `Abs(rel)`: reject empty, absolute paths, any `..` element, NUL, and anything under `.git/`; clean the path; resolve symlinks of the longest existing prefix (for a new file, of its parent chain) and require the result to be `Root` or inside `Root + "/"`. Errors are BAD_INPUT. All other methods call `Abs` first.
- `WriteFile`: create parent dirs (each confined), write to a temp file in the same directory, fsync, rename over the target. Files under `inbox/` are immutable: if the target already exists → `EXISTS`, nothing written.
- `PutDoc`: if the file exists: parse it; `expectRev == ""` → `EXISTS`; `expectRev` differs from the stored rev (`frontmatter.Rev` of the stored doc) → `errs.New(CONFLICT_REV, ...)` with `Extra{"current": <file content>, "rev": <current rev>}`; for a `note`, a changed `evidence` value → BAD_INPUT ("evidence is never rewritten"). Then set the `rev` field to `frontmatter.Rev(d)`, write `d.Bytes()` atomically and return the new rev. `PutDoc` does not call `Validate` (callers validate before writing).
- Never write outside the vault, never follow a symlink out of it, never log file contents to the audit log (paths only), never record secrets.

Tests (`internal/vault/store_test.go`, temp dirs only): `TestWriteConfinement` (`../x`, `/etc/x`, `a/../../x`, a symlink inside the vault pointing outside, `.git/config` → all refused, nothing created outside), `TestAtomicWrite` (no temp files left; content replaced), `TestConflictRev` (stale rev → CONFLICT_REV with current content in Extra; correct rev succeeds and returns a new rev; create over existing → EXISTS), `TestEvidenceImmutable`, `TestInboxImmutable`, `TestTestGuard` (with `t.Setenv("SLOWHUNCH_TEST","1")` and `SLOWHUNCH_PROTECTED` set to a temp dir, `Open` and `GuardPath` refuse it and its subdirectories but allow siblings), `TestAuditAndState`.
