# T024: verify checks and command

Phase 4 · Model: sonnet: read-only integrity checks reusing index, schema and lint types · Depends-on: T023, T014 · Covers: R16 (verify), R5 (rev check), R6 (locator and link check), R8 (inbox ground truth)

## Brief
Add `internal/vault/verify.go` and `internal/cli/cmd_verify.go` + tests. Reuse `vault.Problem` (from `lint.go`), `(*Vault).LoadIndex`, `vault.Validate`, `vault.Links`, `vault.ParseLocator`, `(*Locator).LineRange`, `vault.InboxPlain/InboxLines`, `frontmatter.Rev/LineOf`.

```go
func Verify(v *Vault) ([]Problem, int, error)   // problems sorted by path, line, code; int = number of files checked
```
Re-derive the index from the files and report, never fix:
- `BAD_FRONTMATTER`: every `LoadError`.
- `BAD_FIELD`: `vault.Validate` fails (message = the validation error).
- `REV_MISMATCH`: stored `rev` ≠ `frontmatter.Rev(doc)` (line of `rev`).
- `DANGLING_LINK`: each id from `vault.Links(doc)` that is not in the index (one problem per missing id).
- For notes whose `source` exists and has a non-empty `text_hash`:
  - `INBOX_MISSING`: `inbox/<source>.txt` missing (reported on the source, once).
  - `EVIDENCE_MISMATCH`: `evidence` is not an exact substring of `InboxPlain(stored, medium)`.
  - `LOCATOR_RANGE`: a `line`/`lines` locator outside `1..len(InboxLines)`, or the joined lines of that range do not contain the evidence.
- `LOCATOR_INVALID`: a non-empty `locator` that does not parse (any note).
- Notes without a source, or whose source has no `text_hash` (created by hand), skip the inbox checks.

Command `verify`: strictly read-only (no txn, no audit, no state, no report). Clean → `{"problems": [], "checked": N}` exit 0. Otherwise `errs.New(errs.LintFailed, "<n> verify problems", "inspect the listed ids")` with `Extra{"problems": [...]}` → exit 3; text mode prints `path:line: CODE id message`.

Tests: `internal/vault/verify_test.go` `TestVerifyChecks` (each code triggered once), and `internal/cli/cmd_verify_test.go` `TestVerifyCorrupted`: build a valid vault by writing a poem source with `text_hash`, its inbox file (`vault.FormatInbox`), and two notes with correct revs (`PutDoc`); `verify` exits 0; then hand-corrupt (altered evidence, a dangling `[[ghost]]` link, a wrong rev, a `lines 7-9` locator on a 2-line poem): `verify` exits 3, reports each by note id and its code, and the hash of every file in the vault is unchanged afterwards.
