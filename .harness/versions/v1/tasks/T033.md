# T033: Pipeline item types and gate step

Phase 6 · Model: sonnet: one model call wrapped in clear fail-closed rules · Depends-on: T027, T030, T031, T032, T007 · Covers: R9, R22 (fenced prompt, secret check before sending)

## Brief
Create package `pipeline` (`internal/pipeline/types.go`, `gate.go` + `gate_test.go`). Use `provider.Provider/Prompt/Request/Usage/CallJSON`, `provider/fake` in tests, `intake.Fence/ContainsSecret`, `vault.IsAesthetic`, `errs`.

`types.go` (exact):
```go
type Item struct {
    SourceID, Medium, Title, Author, URL, Note, Hunch string
    Stored []byte   // inbox bytes as stored (vault.FormatInbox output)
    Plain  string   // vault.InboxPlain(Stored, Medium): ground truth for evidence checks
    Delim  string   // per-run delimiter from intake.NewDelimiter
    Force  bool
}
func Class(medium string, hasNote, hasHunch bool) string   // "owner" if medium is own or other, or hasNote, or hasHunch; else "aesthetic" if vault.IsAesthetic(medium); else "factual"
func Header(it Item) string    // plain lines "medium: ...", "title: ...", "author: ...", "owner note: ..." (only non-empty ones); these come from the agent, not the intake text
func FencedText(it Item) string // intake.Fence(string(it.Stored), it.Delim)
```

`gate.go` (exact):
```go
type GateVerdict struct { Keep bool `json:"keep"`; Reason string `json:"reason"` }
func Gate(ctx context.Context, p provider.Provider, pr provider.Prompt, it Item) (keep bool, reason string, u provider.Usage, err error)
```
Rules:
- `intake.ContainsSecret(it.Plain)` → `errs.New(errs.BadInput, "input contains a secret-like string; nothing was sent", ...)`, keep false, no call. This check comes first, even with `Force`.
- `it.Force` → keep true, reason `forced`, no call. Class `owner` → keep true, reason `owner-steered`, no call.
- Otherwise exactly one call: `Request{Role: "gate", Medium: it.Medium, System: pr.Text, User: Header(it) + "\n" + question + "\n\n" + FencedText(it), MaxTokens: 300}` via `provider.CallJSON` into `GateVerdict`. Factual question: "Does this text make a specific, checkable claim with support that is worth keeping as evidence? Answer keep true or false." Aesthetic question: "Is there a line or passage here worth keeping for its craft or for how it reads? Answer keep true or false."
- Fails closed: any error from the call (including invalid output after repair) → keep false, `err` with code PROVIDER_ERROR; the caller counts the item as rejected and writes nothing.

Tests (`internal/pipeline/gate_test.go`, `fake.Fake`): `TestGateFactual` and `TestGateAesthetic` (the user message contains the respective question, the fenced text with the delimiter lines, and not the other question), `TestGateOwnerSkips` (medium own, or a note, or a hunch → no call, keep), `TestGateForce` (no call, keep, even when the fake would reject), `TestGateProviderError` (fake returns an error → keep false, PROVIDER_ERROR), `TestGateRejects` (fake `{"keep": false}` → keep false, no error), `TestGateSecret` (text with `sk-` + 20 chars → BAD_INPUT, zero calls even with Force).
