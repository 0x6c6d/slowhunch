# T009: gitops: init, dirty check, exact-path commit, GIT_MISSING

Phase 2 · Model: opus: subprocess construction and git side effects are Risk items (never push/pull/force, exact paths only) · Depends-on: T002 · Covers: R21

## Brief
Create `internal/gitops` (package `gitops`) + tests. This is the only place in the product that runs `git`.

API (exact):
```go
func Available() bool                       // exec.LookPath("git") succeeds
func IsRepo(dir string) bool                // dir is inside a git work tree
func Init(dir string) error                 // git init -q
type Repo struct { Dir string }
func New(dir string) *Repo
func (r *Repo) Dirty(paths []string) ([]string, error)
func (r *Repo) Commit(paths []string, subject, body string) (string, error)
```
Rules:
- Every call is `exec.Command("git", "-C", dir, ...)` with an argv slice: never a shell, never user text as an option (always put `--` before paths). Allowed subcommands only: `init`, `rev-parse`, `status`, `add`, `rm --cached`, `commit`, `config --get`. Never `push`, `pull`, `fetch`, `reset`, `checkout`, `rebase`, `--force`, `-f`, `-A`, `--all`, or `add .`.
- If git is not on PATH, every function returns `errs.Fatal(errs.GitMissing, "git not found", "install git or use --no-commit")` (`IsRepo`/`Available` return false).
- `Dirty(paths)`: paths are relative to `Dir`; returns (sorted) those that have uncommitted changes of any kind: modified, staged, deleted, or untracked-but-present (`git status --porcelain=v1 -z --untracked-files=all -- <paths>`). A listed path that does not exist and is not tracked is not dirty. Ignored files are not dirty.
- `Commit(paths, subject, body)`: stage exactly `paths` (`git add -- <existing paths>`; for paths that no longer exist, `git rm --cached -q --ignore-unmatch -- <path>`), then commit only those paths (`git commit -q --only -m <subject> -m <body> -- <paths>`, or an equivalent that provably excludes other staged changes). If none of the paths changed, return `"", nil` without committing. Return the full hash of the new HEAD.
- Identity: if `git config --get user.name` or `user.email` is empty in `Dir`, pass `-c user.name=slowhunch -c user.email=slowhunch@localhost`. Always pass `-c commit.gpgsign=false`. Never change repository or global config.
- Errors: code `GIT_MISSING` only when git is absent; any other failing git command returns `errs.Fatal(errs.BadInput, "git <subcommand> failed: <first stderr line>", "")`. (The `CONFLICT` decision belongs to callers, which compare `Dirty` against the paths they will write.)

Tests (`internal/gitops/gitops_test.go`, temp repos only; skip with `t.Skip` only if git is genuinely absent): `TestInitRepo`, `TestConflictDirty` (modified tracked, staged, untracked and deleted files are reported; clean and ignored ones are not), `TestCommitExact` (with an unrelated modified and staged file present, `Commit` of two new files creates one commit whose `git show --stat --name-only HEAD` lists exactly those two; the unrelated file is still modified/staged afterwards; deletion of a tracked file is committed when listed), `TestCommitNothing`, `TestGitMissing` (`t.Setenv("PATH", "")` → `Available()` false, `Commit` error code `GIT_MISSING`).
