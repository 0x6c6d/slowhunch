# T017: list command with filters

Phase 3 · Model: sonnet: read-only command over the index · Depends-on: T011, T013, T014 · Covers: R14 (list with filters)

## Brief
Add `internal/cli/cmd_list.go` + tests. Use `env.openVault()`, `(*Vault).LoadIndex`, `(*Index).All/OfType/MediumOf`, `frontmatter.Doc` getters.

`list [--type T] [--medium M] [--stance S] [--tag X] [--hunch ID] [--state S] [--limit N]`:
- All filters combine with AND; each is optional.
- `--type`: entry type (must be one of note source hunch proposal topic, else BAD_INPUT).
- `--medium`: for notes the medium of their source (`MediumOf`), for sources their own `medium`; other types never match. Unknown medium value → BAD_INPUT.
- `--stance`: notes with that stance (asserts crafts reads, else BAD_INPUT).
- `--tag`: entries whose `tags` contain the value.
- `--hunch`: entries whose `bears_on` contains the id.
- `--state`: hunches in that state (open warming tested dropped, else BAD_INPUT).
- `--limit` default 0 = no limit.
- Result: `{"items": [{"id", "type", "path", "title"}], "count": N}` sorted by id, where `title` is the claim (note), question (hunch), idea (proposal) or title (source, topic). Text mode: one line per item `id  type  title`.
- Read-only: no txn, no commit, no audit line.

Tests (`internal/cli/cmd_list_test.go`; seed files with `create` via `Run` or write them with the vault API): `TestCRUDList` (no filter lists everything sorted), `TestCRUDListFilters` (each filter alone and two combined, including `--medium poem` matching a note through its source), `TestCRUDListBadFilter` (unknown stance → exit 2).
