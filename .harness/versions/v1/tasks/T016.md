# T016: delete command: soft to archive, hard with yes

Phase 3 · Model: opus: deletion is a data-loss Risk item (soft by default, hard needs explicit confirmation) · Depends-on: T011, T013, T014 · Covers: R14 (delete), R21

## Brief
Add `internal/cli/cmd_delete.go` + tests. Use `env.openVault/begin`, `(*Vault).LoadIndex`, `(*Txn).Move/Remove/Commit`.

`delete <id> [--hard --yes]`:
- Unknown id (not in the index) → NOT_FOUND exit 2.
- Default (soft): move `<folder>/<id>.md` to `archive/<id>.md` through `txn.Move`. If `archive/<id>.md` already exists → EXISTS exit 4, nothing moved. Commit (`ids [id]`, counts `archived: 1`); the commit records the removal of the old path and the addition of the archive path. Result `{"id", "archived": "archive/<id>.md", "git": {"commit"}}`.
- `--hard` without `--yes` → BAD_INPUT exit 2 ("hard delete needs --yes"), nothing changed. `--yes` without `--hard` is ignored (soft delete).
- `--hard --yes`: `txn.Remove("<folder>/<id>.md")`, commit (counts `removed: 1`). Result `{"id", "removed": true, "git": {"commit"}}`.
- Never delete `inbox/` files, sources' inbox text or anything outside the indexed entry. Other files that link to the deleted id are left untouched (verify will report dangling links).
- `--dry-run` reports the plan and changes nothing.

Tests (`internal/cli/cmd_delete_test.go`): `TestCRUDDeleteSoft` (file now in `archive/`, gone from its folder, `get` → NOT_FOUND, commit shows both paths), `TestCRUDDeleteHardNeedsYes` (exit 2, file byte-identical, no commit), `TestCRUDDeleteHard` (file gone, committed), `TestCRUDDeleteMissing` (NOT_FOUND), `TestCRUDDeleteDryRun` (tree unchanged).

## Verification
