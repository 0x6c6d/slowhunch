# T019: hunch add, evidence, state, due commands

Phase 3 · Model: sonnet: four small commands on existing vault APIs · Depends-on: T006, T011, T013, T014 · Covers: R14 (hunch commands), R2 (hunch fields)

## Brief
Add `internal/cli/cmd_hunch.go` + tests, registering two-word commands `hunch add`, `hunch evidence`, `hunch state`, `hunch due`. Use `env.openVault/begin/today`, `vault.KebabID/UniqueID/Validate`, `(*Vault).LoadIndex`, `(*Txn).PutDoc/Commit`, `frontmatter.Rev`. Tests can fix the clock by replacing the package variable `nowFunc`.

- `hunch add "<question>" [--next-test T] [--revisit YYYY-MM-DD] [--tags a,b] [--author A]`: id `UniqueID(KebabID(question))`; fields `id type=hunch created updated author(default human) rev tags question state=open next_test revisit evidence=[]` (omit empty optional scalars); validate; write `hunches/<id>.md`; commit (counts `hunches: 1`). Result `{"id", "path", "rev", "git": {"commit"}}`. Empty question → BAD_INPUT.
- `hunch evidence <id> --note <note-id> --relation supports|weakens`: hunch must exist and be a hunch (NOT_FOUND / BAD_INPUT); the note must exist and be a note (NOT_FOUND); relation must be valid (BAD_INPUT). Append `{date: today, note, relation}` to `evidence`; set `updated`; if state is `open`, it becomes `warming`. Write with the current rev; commit (counts `evidence: 1`). Result `{"id", "evidence_count", "state", "git"}`.
- `hunch state <id> <state>`: state in open warming tested dropped (else BAD_INPUT); write, commit (counts `state: <state>`).
- `hunch due`: read-only. Hunches with `revisit` ≤ today and state ≠ dropped, sorted by revisit then id. Result `{"due": [{"id", "question", "revisit", "state"}], "today"}`.

Tests (`internal/cli/cmd_hunch_test.go`): `TestHunchAdd`, `TestHunchEvidence` (dated entry with today's date; open → warming; unknown note → NOT_FOUND, file unchanged; bad relation → exit 2), `TestHunchState`, `TestHunchDue` (fixed clock 2026-11-05: revisit 2026-11-01 listed, 2026-12-01 not, dropped not, no revisit not).
